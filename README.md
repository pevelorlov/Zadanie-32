# DeepSeek Agent — ассистент разработчика - Задание дня 32

Локальное Windows-приложение: чаты с DeepSeek API, документация проектов в RAG,
Git и файловые инструменты через MCP, память, этапы задач и расписания.
Ассистент может изучать собственный проект либо публичный GitHub/локальную папку.

**Текущее устройство зафиксировано 17 октября 2026 года.** Начните с
[содержания документации](docs/README.md) и [состояния реализации](docs/CURRENT_STATE.md).

## Запуск

Создайте .venv, установите requirements.txt и Node-зависимости через npm ci.
Добавьте DEEPSEEK_API_KEY в .env по образцу .env.example. Запустите run.bat.
Откроется адрес 127.0.0.1 на свободном порту 5000–5100.
[Подробная установка, переменные и параметры модели](docs/CONFIGURATION.md).

Генеративный провайдер только DeepSeek. Пакет openai — совместимый SDK,
а локальные E5/reranker/Whisper выполняют поиск и распознавание, не генерацию ответов.

## Основные сценарии

| Действие | Как пользоваться |
| --- | --- |
| Спросить о проекте | `/help вопрос`; `/help` без вопроса показывает локальную справку |
| Подключить репозиторий | «＋ Проект» → GitHub или локальная папка → дождаться индексации |
| Переключить контекст | «Рабочий проект»; открытие чата также выбирает его проект |
| Создать отдельную задачу | «＋ Диалог» внутри выбранного проекта |
| Управлять инструментами | Кнопка «MCP» рядом с настройками запроса |
| Обновить знания | «Управление RAG» → обновить документацию и оба индекса |
| Сохранить отчёт | Явно попросить экспорт; создаётся новый Markdown в reports рабочего корня |
| Запланировать поручение | «Расписание»; будущие запуски могут расходовать DeepSeek API |

Проект объединяет чаты, память, RAG и корни Git/Filesystem. Обычный чат внешнего
проекта получает его документацию автоматически. Личная память остаётся
у профиля; память задачи и ветки остаются у диалога.
[Руководство пользователя](docs/USER_GUIDE.md), [рабочие проекты](docs/WORKSPACES.md).

## Возможности и границы

Четыре режима истории full/summary/sliding/facts сохранены; ветки работают
поверх каждого. Память пользователя/проекта и память задачи — независимые слои.
Машина задач управляет planning → execution → validation → done, контроллером
и артефактами. Её можно отключить для обычного чата.

Project MCP читает текущую ветку/commit и список путей. Filesystem сейчас
предоставляет модели безопасный явный экспорт отчёта; произвольное редактирование
исходников не реализовано. Scheduler MCP управляет инструментами расписаний;
его выключение не останавливает фоновый исполнитель существующих заданий.
Старые внешние погодные/экономические/энциклопедические MCP удалены.

RAG индексирует документацию/описания API и схем, а не весь исходный код.
Git-сведения получаются заново через инструмент. GitHub-клон не обновляется
автоматически. Документы индексируются локально, но найденный контекст при
ответе передаётся DeepSeek. Полные ограничения — [SECURITY_AND_LIMITS](docs/SECURITY_AND_LIMITS.md).

Канонические документы — этот README и актуальные docs. Учебные материалы
прошлых дней сохранены в [архиве](docs/archive/README.md), который исключён из
собственного RAG. Копии rag_documents и индексы восстанавливаются из источников.

```powershell
.\.venv\Scripts\python.exe scripts\generate_api_reference.py
.\.venv\Scripts\python.exe scripts\check_documentation.py
.\.venv\Scripts\python.exe scripts\rebuild_rag_index.py
```

Контрольная точка описана в docs/CURRENT_STATE.md, SHA-256 поставки —
в docs/source_snapshot.json. Это фиксация документации/исходников без создания
Git-коммита или удаления пользовательских данных.
