# RAG: документация, поиск и проверка источников

## Два разных понятия

Документы — долговременная база знаний проекта. Чанки извлекаются по конкретному
вопросу и временно добавляются в контекст модели. История диалога, личная память,
task_memory и MCP-результаты не становятся автоматически документами RAG.
Исходный код целиком не индексируется: сведения о нём должны быть изложены в
документации либо получены поддерживаемым инструментом.

## Корпус самого ассистента

ProjectDocumentation.sources выбирает корневой README.md и Markdown в docs,
исключая docs/archive, символические ссылки, выход за корень и исторические
файлы с RESULTS/COMPARISON/SCENARIOS/CONTROL_AFTER_FIX в имени. Старые руководства
дней 21–25 перенесены в архив и не служат описанием текущего приложения.
Пользовательские профили, диалоги, .env, журналы и загруженные GitHub-клоны не
включаются в этот корпус.

sync копирует документы в rag_documents с относительными путями. Manifest
.project-manifest.json хранит список управляемых копий и SHA-256 отпечаток их
канонических источников. При обновлении удаляются только ранее управляемые
копии, которых больше нет в источниках. Канонический docs не удаляется.
Ручные посторонние документы в папке копий не очищаются этим механизмом.

Для внешнего workspace набор расширений и каталогов шире; пределы и размещение
описаны в WORKSPACES.md. Индексы и журналы сравнений между проектами раздельны.

## Построение индекса

POST /api/rag/index синхронизирует выбранную документацию и запускает фоновую
индексацию; ответ 202 содержит job. Обновление двух стратегий выполняется одним
запуском. Через GET state видны running, phase, errors, источники и latest_run.
Новый поиск использует последний завершённый сохранённый запуск, а не частично
построенный индекс. Несовместимая embedding-модель требует перестроения.

Загрузчики в document_index/loaders.py понимают PDF, DOCX, TXT, MD, HTML/HTM.
OCR нет: PDF без текстового слоя может не дать полезных фрагментов.
fixed режет текст по токенам с overlap; structural учитывает блоки и заголовки,
а слишком длинные блоки дробит. Эмбеддинги E5 используют passage/query-префиксы,
локальную CPU-модель и нормализацию. SQLite хранит тексты, метаданные и векторы.
Поиск выполняется локальным ранжированием, отдельного векторного сервера нет.

Размеры/overlap передаются при построении; скрипт rebuild_rag_index.py повторяет
параметры последнего запуска (при отсутствии — размер 350 и overlap 50).
Загрузчики пропускают точные дубликаты файлов по хешу; ошибки отражаются в запуске.

## Настройки поиска обычного чата

| Параметр | Значения / контракт |
| --- | --- |
| strategy | fixed, structural, combined |
| mode | baseline, rewrite, filter, rerank, combined |
| routing_mode | strict или auto |
| candidate_k | 1–100 кандидатов |
| final_k | 1–20, не больше candidate_k |
| similarity_threshold | От −1 до 1, начальное значение 0.83 |
| verified | Проверка релевантности и подтверждений цитатами |

baseline оставляет векторный поиск. rewrite делает дополнительный LLM-запрос
для формулировки запроса. filter применяет порог similarity. rerank использует
локальный cross-encoder. combined объединяет эти этапы. Объединение стратегий
fixed/structural и режим combined pipeline — разные настройки.

auto выбирает rag/task/tools/hybrid/general: сначала детерминированные правила,
при необходимости LLM-классификатор. Упоминание погоды в старом правиле маршрута
не означает наличие погодного MCP — он удалён. Вопросы о текущей задаче могут
использовать её состояние; общие вопросы — знания модели без документов.
«Только база» отключает автоматическую классификацию, но не является сетевым
песочником: ответ всё равно генерируется DeepSeek. Явная просьба «Ответь вне базы
знаний» обрабатывается отдельным разрешением выхода из документального ответа.

Внешний workspace принудительно задаёт baseline/structural/strict при готовом
индексе. Это не то же самое, что verified: автоматическая привязка источников
не включает строгую проверку цитат.

## Проверяемый ответ и /help

В verified включается relevance gate независимо от выбранного pipeline-режима.
Ответ должен быть связан с переданными chunk_id и дословными цитатами. Проверка
цитаты детерминированная; семантическое подтверждение — отдельная оценка модели.
Есть попытки исправления/дополнительного ответа; при недостатке подтверждений
возвращается явное «Не знаю». Сходство векторов не является вероятностью истинности.

/help использует structural baseline top-8 без rewrite/rerank/автоклассификатора.
Для вопросов о схеме добавляет top-4 и удаляет повторные чанки. Затем получает
свежий Project MCP и вызывает модель. Источники внизу — перечень контекста,
а не результат verified-проверки каждого утверждения.

## Хранение и оценка

Полные документы и чанки остаются локально. Найденные фрагменты, вопрос и нужный
контекст отправляются DeepSeek при генерации; rewrite/оценка также могут быть
сетевыми. technical ответа содержит компактный RAG-снимок; не следует считать
каждый прошлый ответ актуальной копией документации.

UI сравнения ответов и pipeline/evidence-оценок хранит отдельный rag_evaluations.json.
Сравнение «без RAG / с RAG» делает два генеративных запроса и не продолжает чат.
Контрольный набор текущего проекта — day31_control_questions.json. Качество
поиска проверяйте отдельно от литературного качества ответа и MCP-аудита.
