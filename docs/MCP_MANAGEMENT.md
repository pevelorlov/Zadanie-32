# Управление MCP

Кнопка **MCP** рядом с «Настройками запроса» открывает единое окно всех серверов.
В окне видны выбранный проект, разрешения, соединения, рабочие папки,
ошибки и доступные инструменты. Старые карточки «Все MCP» и «Filesystem MCP»
из правой панели перенесены сюда. Из окна расписаний также можно открыть управление MCP.

## Серверы и границы

| Сервер | Инструменты для ассистента | Область |
| --- | --- | --- |
| Project | get_git_branch, list_project_files; только чтение | Корень проекта текущего диалога |
| Filesystem | При явном экспорте отчёта модели доступен write_file с принудительным безопасным путём | Для самого ассистента — workspace/reports; для внешнего проекта — reports в его корне |
| Scheduler | Создание, просмотр и изменение расписаний в пределах разрешённого набора инструментов | Общее хранилище data/scheduler.sqlite3; задания связаны с профилями и проектами |

«Инструменты» показывает каталог подключённого сервера и схемы аргументов.
Каталог сервера может быть шире набора, который приложение разрешает модели.
Например, наличие read_text_file в каталоге Filesystem не означает, что обычный
чат уже умеет произвольно читать и редактировать исходники: сейчас реализован явный экспорт отчётов.
Project исключает секреты, runtime-данные, модели и зависимости из списка файлов.

## Разрешение и соединение

- «Разрешить» — постоянное разрешение типа сервера для **всех профилей и проектов**.
  Само включение не запускает процесс.
- «Запустить» / «Остановить» управляют текущим соединением. Остановка не запрещает
  последующий автоматический запуск.
- Отключение отдельного разрешения останавливает все уже созданные соединения
  этого типа, включая другие рабочие проекты. Разрешение проверяется перед
  выдачей инструментов модели и перед каждым вызовом.
- «Отключить все MCP» блокирует все три сервера и останавливает их соединения.
  «Разрешить MCP» снимает общий запрет, сохраняя отдельные запреты.

Project запускается по необходимости для /help и вопросов о проекте.
Filesystem запускается для явной просьбы сохранить отчёт.
Scheduler MCP подключается при запуске приложения, если разрешён.
При переключении рабочего проекта окно показывает его корни Project и Filesystem;
разрешения остаются общими. Корень диалога определяется его project_id.

Общий запрет хранится в data/mcp_control.json. Индивидуальные разрешения —
в data/mcp_server_control.json: объект с булевыми project, filesystem, scheduler.
При отсутствии файла все три разрешены; повреждённый файл запрещает их использование.

## Расписания

Scheduler MCP и фоновый исполнитель — разные части приложения. Отключение
Scheduler MCP запрещает инструменты, но **не отменяет и не приостанавливает
ранее созданные задания**. Внизу окна отдельно показано состояние исполнителя;
кнопка «Открыть расписания» ведёт к управлению заданиями. При необходимости
приостановите нужные задания в этом разделе. MCP-запреты продолжают действовать
и при выполнении заданий: запрещённые инструменты недоступны.

## Индикация в чате

Синяя панель появляется только при наличии записи о начавшемся вызове инструмента.
Ожидание выбора инструмента моделью не показывает MCP-панель. Для реальных вызовов
видны сервер, имя, аргументы с маскированием чувствительных полей и результат
«выполняется», «готово» или «ошибка». В истории сохраняется фактический аудит вызовов.

## API

- GET /api/mcp/servers — разрешения, состояния всех трёх серверов, области работы
  выбранного проекта и отдельное состояние исполнителя. Не запускает серверы.
- POST /api/mcp/servers/{project|filesystem|scheduler}/{enable|disable|start|stop|tools} —
  управление разрешениями, соединениями и каталогом инструментов.
- Общий выключатель: POST /api/mcp-control/enable и /disable.
- Старые маршруты /api/mcp/start, /stop, /tools, /status относятся к Filesystem;
  /api/scheduler/tools — к Scheduler. Они также соблюдают индивидуальные запреты.

Новые управляющие маршруты start/tools возвращают 403 при запрете, 503 при ошибке
соединения и 404 для неизвестного сервера/действия. Старые маршруты сохраняют
ответ 409 при запрете. disable сохраняет запрет даже при ошибке остановки;
такие ошибки возвращаются в errors, состояние соединения видно отдельно.
