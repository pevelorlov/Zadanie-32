# Архитектурные решения текущего проекта

## DeepSeek API и локальный поиск

Единственный генеративный провайдер — DeepSeekProvider. Пакет openai — совместимый
SDK; запросы идут на api.deepseek.com. Эмбеддинги, reranker и Whisper работают
локально и не являются дополнительными провайдерами ответов.

## Явный /help и свежий Git

/help вопрос ищет текущую документацию и получает фактический контекст Project
MCP заново. Ветка Git не индексируется, поскольку меняется независимо от docs.
Список источников — аудит контекста, а не гарантия каждого утверждения модели.
Старые приложения источников не возвращаются в новые запросы как доказательства.

## Минимальный набор MCP

Project нужен для Git и структуры, Filesystem — для явного файлового экспорта,
Scheduler — для фоновых задач. Внешние погодные, экономические и справочные MCP
удалены из кода, UI, конфигурации и зависимостей. Общий выключатель блокирует
запуск и каждый tools/call. Содержание исходников Project MCP не читает.

## Совместимость и изоляция

JSON schema v3 расширяется совместимо. Дерево работает поверх full, summary,
sliding и facts. Locked-память сохраняется при автоматических обновлениях.
Failed-запросы не входят в контекст. Task Memory независима от автомата этапов.
/help не меняет этапы и не записывает исходники. Полные RAG-чанки хранятся в
SQLite; в JSON — компактные ссылки и аудит. Исторические отчёты со старыми
примерами диалогов не индексируются. При переходе на день 31 по отдельному прямому указанию пользователя были
очищены старые профили, диалоги и индекс. Это историческая миграция,
а не правило очистки при каждом запуске. Текущие пользовательские данные,
.env и модели при обновлении документации не удаляются.

## Рабочий проект объединяет все контексты

workspace добавляется к существующему проекту памяти. Диалоги не меняют
репозиторий задним числом; переключение открывает отдельную историю. RAG, Git,
Filesystem и расписания используют корень проекта. Индексы и сравнения раздельны,
а embeddings-модель общая. Код импортированного репозитория не исполняется.


## Единое управление MCP

Разрешение типа сервера (Project, Filesystem, Scheduler) постоянно и общее для
приложения, соединения Project/Filesystem принадлежат рабочим проектам.
Общий запрет имеет приоритет; его снятие не сбрасывает индивидуальные запреты.
Остановка соединения допускает автоматический запуск, отключение разрешения запрещает его.
Проверка выполняется перед предоставлением инструментов и перед tools/call.
Scheduler MCP отделён от исполнителя расписаний: его отключение не отменяет задания.
Индикация MCP в чате отражает только начавшиеся вызовы, а не ожидание ответа модели.


## Текущий справочник отделён от учебной истории

Канонические руководства организованы по подсистемам в docs; README задаёт
навигацию. Прежние материалы дней 21–25 и результаты дня 31 сохраняются в
соответствующем архиве docs/archive с исходными именами. Архив исключён из
собственного корпуса ProjectDocumentation независимо от имени файла.
Текущая точка описывается CURRENT_STATE и source_snapshot.json с хешами;
каталог HTTP генерируется из кода. Полные хеши не включаются в RAG как отдельный
документ, а актуальные человекочитаемые руководства индексируются.

## Ревью PR отделено от чата и исполняемого кода PR

CLI code_review.py использует общий DeepSeekProvider, но собственный временный
BM25-корпус кода и документации конкретного Git head. Индекс /help остаётся
документационным. Ревью не запускает Flask, MCP, код PR и зависимости из PR.
Для домашнего runner workflow берётся из доверенной base через pull_request_target;
head доступен только как Git-объекты. Активация требует разрешённого репозитория
и явного флага, по умолчанию выключена. Публикация отчёта не исправляет код
и не выполняет merge. Подключение правильного remote и push — отдельный этап.
