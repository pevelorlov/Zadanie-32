рабочих проектов и единого управления MCP. Исходный код определяет поведение;
руководства объясняют его и входят в собственный RAG ассистента.

## Актуальная документация и архив

Канонические документы — README.md в корне и Markdown вне docs/archive.
В [архиве](archive/README.md) сохранены прежние учебные руководства и отчёты.
Их формулировки описывают состояние соответствующего дня, а не текущую версию.
Архив не входит в собственный RAG. Контрольные JSON-вопросы прошлых дней оставлены
для воспроизводимости; приложение загружает только day31_control_questions.json.

Копии для поиска находятся в rag_documents; править нужно канонические документы,
затем пересобирать индекс. Схемы/API — текстовые описания реализации, а не отдельный
OpenAPI-сервер или файл миграций. Текущая Git-ветка всегда получается через MCP,
а не из датированного описания или сохранённого ответа.

## Как поддерживать справочник

Изменение поведения сопровождается изменением соответствующего руководства.
Новый модуль добавляется в PROJECT_MAP; устойчивое решение — в DECISIONS.
Каталог HTTP-маршрутов генерируется из AST app.py. Проверки и команды обновления
описаны в OPERATIONS. Файл source_snapshot.json содержит SHA-256 исходников
зафиксированной точки; он не является резервной копией кода или пользовательских данных.
