# Контекст, ветки и память

## Независимые слои

| Механизм | Где живёт | Что даёт текущему запросу |
| --- | --- | --- |
| Политика разработчика | config/agent_policy.json | Постоянные правила, UI только читает |
| Профиль и личная память | data/profiles.json | Предпочтения и записи автора сообщения |
| Проектная память | data/projects/<id>.json | Решения и сведения общего проекта |
| История, summary, Sticky Facts | JSON диалога | Контекст активной ветки по выбранной стратегии |
| Память задачи | task_memory и task_memory_revisions диалога | Цель, уточнения, ограничения, термины, решения, открытые вопросы |
| Этап и handoff | task_state и task_handoffs диалога | Состояние процесса и передача между этапами |
| RAG | SQLite выбранного workspace | Документальные фрагменты по вопросу |
| MCP | Живые вызовы + аудит ответа | Актуальные результаты инструментов |

Контекстное окно — собранное представление этих данных, а не ещё одно
хранилище. Политика, память, история и документы имеют разные источники и
сроки актуальности. Прежняя Git-ветка в памяти не заменяет свежий MCP-вызов.

## Дерево сообщений

parent_id задаёт связь с родителем; exchange_id связывает вопрос с ответом.
context_management.active_leaf_id выбирает активный путь. begin_branch создаёт
точку продолжения; select_branch переключает путь. Альтернативы сохраняются,
но в текущий контекст не подмешиваются. Старые линейные истории нормализуются
при чтении без удаления исходных сообщений. Ветвление не является отдельным
пятым режимом.

completed_exchanges учитывает успешные связанные user/assistant обмены.
Сообщения pending/failed и служебные event не становятся успешной историей.

## Четыре стратегии истории

| Режим | Отбор |
| --- | --- |
| full | Все успешные обмены активного пути (или текущего этапа) |
| summary | Версия накопленной сводки + ещё не покрытые ею обмены |
| sliding | До window−1 прошлых обменов + новое сообщение |
| facts | Sticky Facts + до window−1 прошлых обменов + новое сообщение |

Окна sliding/facts допускают 1–50, исходное значение 5. При окне 1 прежние
обмены не передаются. Summary оставляет минимум пять свежих обменов и сворачивает
старые партиями по пять. Поэтому первое сворачивание возможно при десяти
завершённых обменах; между партиями несвёрнутых обменов может быть больше пяти.
Сводка не удаляет оригиналы. Ревизии содержат covered_exchange_ids и происхождение.
После изменения ветки несовместимое покрытие сбрасывается.

Sticky Facts извлекаются отдельно в режиме facts. Ручные locked=true записи
автоматика не переписывает; изменения и usage хранятся в fact_revisions.
При включённой машине задач request_history ограничивает обмены/summary/facts
текущим stage_run_id, дополняя их активным handoff. При выключенной машине
используется вся подходящая активная ветка. /help берёт историю без этапного
ограничения и не обновляет память.

## Личная и проектная память

Профиль задаёт имя, язык, технический уровень, подробность, тон, структуру,
предпочитаемые/нежелательные форматы и custom_instructions. Он не заменяет пресет.
Проект задаёт общую память, владельца и participant_profile_ids. Участники видят
проектные диалоги и общую память; личные предпочтения других людей не включаются
в запрос автора. Это правила локальной видимости, не система сетевой авторизации.

Manual-запись имеет source=manual и locked=true. Автоматическое извлечение
создаёт learned-записи с происхождением (диалог/обмен/проект), обновляет learned
с тем же ключом и пропускает точные дубликаты. Совпадение с manual не меняет её.
Закрепление переводит запись в manual. Неактивные записи не передаются модели.
Статус confidence=confirmed в текущей схеме не означает независимую проверку
истинности автоматически извлечённого факта.

После успешного обычного ответа при включённых переключателях личного или
проектного извлечения выполняется вспомогательный запрос DeepSeek. Максимум
12 кандидатов проходит валидацию scope/kind/key/value и фильтр секретов.
Ключ — до 120 символов, значение — до 2000. На слой контекста выбирается до
30 записей/12 000 символов, сначала manual, затем learned. Ошибка извлечения
не отменяет уже сохранённый основной ответ; usage учитывается отдельно.

## Память текущей задачи

task_memory по умолчанию выключена и управляется собственным enabled.
В ней goal (до 2000 символов), clarifications/constraints/decisions/open_questions
и terms. Списки ограничены 30 элементами по 1000 символов. После успешного
ответа модель обновляет структурированный снимок; сервер валидирует его.
При ошибке разбора прежний снимок сохраняется, ревизия получает failed.
Успешное изменение увеличивает revision; история ограничена последними 100
ревизиями. Выключение памяти не очищает сохранённые данные.

Память задачи не является поиском по документам, stage machine или полным
архивом чата. Она включается в контекст независимо от общего выключателя
машины задач. Интерфейс показывает её цель, списки и ревизию.

## Снимки и стоимость

technical.memory_context успешного ответа содержит применённый профиль,
проект и копии отобранных записей. «Какая память использована» открывает этот
исторический снимок; правка памяти сегодня его не изменяет. technical.task_memory,
context_management и task_handoff_context фиксируют другие применённые слои.
Полный system prompt в этот снимок не копируется, но текстовые значения памяти
сами по себе могут быть личными данными.

Основные токены, summary, facts, долговременное извлечение, task_memory и handoff
учитываются раздельно. Один видимый ответ может потребовать несколько платных
вызовов. Метаданные usage — отчёт провайдера/агрегация приложения; не счёт биллинга.

## Совместимость и перенос

JSON-диалоги остаются schema_version=3. data/memory/user_memory.json служит
источником прежней миграции в основной профиль; старый файл не удаляется.
Проекты без workspace сохраняют память, но используют корень самого ассистента.
При переключении рабочего проекта память задачи, ветки и история не переносятся.
Импорт создаёт новые ID диалога/проекта; экспорт не включает всю библиотеку
профилей, политику, SQLite-индексы или физический GitHub-клон. Поле workspace
в копии проекта может ссылаться на прежний локальный путь — перенос на другую
машину требует проверки и повторного подключения, автоматического клонирования
при импорте пакета нет.

Источники: context_manager.py, memory_manager.py, task_memory.py, storage.py,
Agent.reply и обновления после ответа в app.py. Архивные описания прежних дней
не определяют нынешние ограничения.
