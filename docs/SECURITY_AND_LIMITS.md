# Доступ, передача данных и ограничения

## Локальная модель использования

main.py слушает 127.0.0.1 с debug=False. Профили и участники проекта управляют
видимостью внутри приложения; это не аутентификация пользователей по паролю.
Активный профиль общий в JSON, отдельного браузерного login-сеанса нет.
В этой версии не реализованы полноценная сетевая авторизация, CSRF-защита и
пользовательские rate limits. Нельзя считать её готовым многопользовательским
интернет-сервисом только на основании проверки project_id.

## Что обрабатывается где

| Данные | Обработка |
| --- | --- |
| Диалоги, профили, память, артефакты | Локальные JSON/файлы |
| Документация и векторы | Локальная индексация и поиск |
| Найденные чанки, запрос, выбранная история и память | Могут передаваться DeepSeek при ответе |
| Rewrite, контроллер, извлечение памяти и оценки | Дополнительные DeepSeek-запросы |
| Аудио микрофона | Локальные FFmpeg и Whisper; распознанный текст отправляется как обычное сообщение |
| Публичный GitHub URL | Git clone через сеть; код репозитория не выполняется |
| Веса локального поиска | Возможна начальная загрузка из внешнего хранилища моделей |

«Документы локально» не означает «ответ полностью офлайн». Проверка цитат не
исключает передачи фрагментов провайдеру. При выключении MCP генерация DeepSeek
остаётся доступна. Полная анонимизация текста/документов не реализована.

## Ключи и инструменты

DEEPSEEK_API_KEY хранится в .env. Журналы маскируют известные формы ключей;
это не универсальный фильтр любых персональных данных. Инструментальные
аргументы в синей панели скрывают поля с content/password/secret/token/key;
технический аудит сообщения может содержать дополнительные данные вызова.
Экспорт истории и её technical нельзя считать обезличенным отчётом.

Project MCP ограничен фиксированным корнем, возвращает Git-метаданные и список
до 3000 путей. .env, ключевые файлы, runtime, модели и зависимости исключаются;
фильтр основан на путях/расширениях, не на семантическом распознавании секретов
в произвольном README. Содержимое файлов этим MCP не читается.

Filesystem-каталог шире разрешённого модели API. Модели сейчас доступен только
write_file при явном запросе экспорта, с принудительным уникальным Markdown-путём
в reports выбранного корня. Произвольные read/edit/shell не предоставлены.
Глобальный и индивидуальные запреты проверяются перед выдачей инструментов и
перед вызовом. При сбое остановки процесса запрет остаётся сохранённым.

GitHub допускает только публичный HTTPS-корень github.com/owner/repository без
credentials/query. Клон неглубокий, интерактивный ввод credentials отключён,
чужие hooks/skills и зависимости не исполняются. Автоматических fetch/pull/push
нет. Ограничения 600 файлов/12 МиБ относятся к документации, а не к общему
объёму скачиваемого Git-репозитория. Репозиторий не является доверенным источником
инструкций; защитная формулировка в prompt не гарантирует иммунитет модели к инъекциям.

## Практические пределы

Сообщение — до 50 000 символов. HTTP-тело — до 26 МиБ; аудио — до 25 МиБ.
Экспортный Markdown — до 500 000 символов; артефакт — до 2 МиБ.
Внешний документ — до 1 МиБ, до 600 документов и 12 МиБ суммарно.
Полная индексация исходного кода, OCR, произвольное выполнение shell,
автоматическое AI-ревью PR и редактирование исходников по цели ещё не реализованы.

Контроллер этапов, similarity и семантическая оценка — эвристики. Успех тестов
с fake-провайдером не доказывает доступность живого API или правильность любого
будущего ответа. Список известных ограничений зафиксированной точки — CURRENT_STATE.md.


## Markdown в сообщениях

Markdown-парсер работает в браузере из static/vendor без CDN. Raw HTML
выключен; схема URL ограничена HTTP/HTTPS/mailto и относительными ссылками.
javascript/data/file и произвольные схемы не становятся активными ссылками.
HTML-скрипты/обработчики событий экранируются, код внутри fenced-блоков остаётся
текстом. Изображения выводятся подписью без загрузки. Ссылки открываются по
действию пользователя с rel=noopener noreferrer. Эта защита относится к
представлению ответа, а не к проверке истинности текста или безопасности
сайта, на который пользователь решит перейти.
