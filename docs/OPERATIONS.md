# Эксплуатация, обновление и диагностика

## Обычный запуск и остановка

Запускайте run.bat из папки приложения. Используется .venv/Scripts/python.exe
и main.py; выбранный локальный адрес выводится в консоль. Не запускайте второй
экземпляр с той же папкой data для обхода занятого порта. main.py сам ищет
свободный порт. Ctrl+C завершает Flask, исполнитель, все MCP-соединения и Whisper.

Прямой запуск app.py использует другой вход (порт 5000); для пользователя
основным остаётся run.bat. После изменений Python/шаблонов перезапустите сервер,
затем обновите страницу. debug/hot reload в обычном запуске не включены.

## Обновление документации и RAG

Канонические источники — README.md и актуальные docs вне archive. Не редактируйте
копии rag_documents как основной справочник. После изменения API выполните
генератор каталога, затем проверку документов и перестроение индекса:

```powershell
.\.venv\Scripts\python.exe scripts\generate_api_reference.py
.\.venv\Scripts\python.exe scripts\check_documentation.py
.\.venv\Scripts\python.exe scripts\rebuild_rag_index.py
```

rebuild восстанавливает **собственный** индекс ассистента, не индекс выбранного
внешнего проекта. Для внешнего выберите проект в UI и нажмите обновление в
«Управлении RAG». Обновление GitHub-документации читает имеющийся клон и не делает
fetch/pull. Состояние stale означает изменение канонических источников после
синхронизации; успешный latest_run проверяется отдельно.

Индексация и локальный search не вызывают генеративный API. В первый запуск
локальных поисковых моделей могут скачиваться веса. Не запускайте несколько
индексаторов одного корпуса одновременно.

## Контрольная точка

Текущее состояние описано в CURRENT_STATE.md. scripts/document_snapshot.py
создаёт docs/source_snapshot.json: дата в UTC+07, исходный Git HEAD/ветка,
признак незакоммиченных изменений и SHA-256 файлов исходников/канонических docs.
Снимок содержит хеши и пути, а не содержимое приватных runtime-данных.

```powershell
.\.venv\Scripts\python.exe scripts\document_snapshot.py
.\.venv\Scripts\python.exe scripts\document_snapshot.py --check
```

Первая команда фиксирует новую точку и заменяет manifest; вторая только сравнивает
файлы и возвращает ненулевой код при расхождении. Git HEAD сам по себе не описывает
незакоммиченные правки; для этой поставки используйте также хеши. Снимок не создаёт
Git-коммит, tag, архив кода или резервную копию данных.

## Что сохранять в резервную копию

Остановите приложение перед файловым копированием. Сохраните исходники, config,
канонические docs, весь data, нужные отчёты workspace/reports, собственные
rag_documents и локальные рабочие репозитории. data содержит SQLite, проекты,
диалоги, артефакты и выключатели; при копировании работающей SQLite легко получить
несогласованные файлы WAL, поэтому копируйте после штатной остановки.

.env храните отдельно как секрет. Модели/инструменты можно восстановить загрузкой,
но для полностью офлайн-переноса нужны и они. Внешние local-проекты лежат вне
папки приложения: они не попадут в бэкап только data. Абсолютные workspace.root
после переноса могут стать недействительными — переподключите/восстановите папки.
Экспорт одного чата не заменяет такой бэкап. Эта инструкция не выполняет
автоматическое копирование или удаление данных.

## Диагностика

| Симптом | Проверка |
| --- | --- |
| Нет ответа DeepSeek | Ключ в .env без публикации значения; сеть; error и X-Request-ID |
| Пустой/оборванный ответ | finish_reason, reasoning_content, max_tokens в technical |
| Устаревшие сведения | Выбранный проект, stale, latest_run, реальные источники ответа |
| Неверная ветка | Успешный get_git_branch именно выбранного корня; для GitHub это локальный клон |
| MCP не запускается | Общий и индивидуальный запреты, phase/error, Node/Python/Git, каталог инструментов |
| Расписание не сработало | Исполнитель, status/missed, next_run_at с UTC+07, последнее failed/error |
| Не работает микрофон | Разрешение браузера, /api/voice/status, файлы Whisper/модели/FFmpeg, порт 8091 |
| Нет полезного текста из PDF | Текстовый слой; OCR не реализован |

Журналы logging_setup: logs/app.log и logs/errors.log, ротация по 5 МиБ,
до пяти резервных файлов. X-Request-ID связывает запрос и лог. В отдельных
диагностических запусках вывод процесса может дополнительно перенаправляться
в другой файл; он не заменяет штатные журналы.

## Проверки разработчика

```powershell
.\.venv\Scripts\python.exe -m unittest -q
.\.venv\Scripts\python.exe -m py_compile agent.py context_manager.py storage.py app.py developer_help.py
node --check static\app.js
node scripts\test_mcp_activity_ui.js
node scripts\test_markdown_ui.js
git diff --check
.\.venv\Scripts\python.exe scripts\check_documentation.py
```

Тесты используют временные данные и fake-провайдеры. Они не подтверждают живой
DeepSeek или текущую доступность GitHub. Изменённый UI проверяется дополнительно
в браузере без реального LLM-вызова. Результаты текущей ревизии — CURRENT_STATE.md;
исторические протоколы хранятся в archive и не являются новым прогоном тестов.


Браузерная сборка markdown-it хранится в static/vendor вместе с лицензией.
После обновления npm-версии перескопируйте соответствующий UMD-файл из
node_modules/markdown-it/dist/browser и лицензию. Проверяйте raw HTML, опасные
ссылки, сохранность кода и отображение таблиц. Автоматические проверки Markdown
не обращаются к DeepSeek; браузерный стенд использует временные диалоги.
