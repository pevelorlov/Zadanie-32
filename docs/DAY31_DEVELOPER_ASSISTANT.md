# День 31: ассистент разработчика

## Назначение

Ассистент отвечает на вопросы о выбранном рабочем проекте. Подключение других
репозиториев и работа обычного чата описаны в WORKSPACES.md. По умолчанию подключён корень исходников запущенной копии (BASE_DIR).
Проект с workspace выбирает свою папку, индекс, Git и файловые инструменты. Модель ответов — существующий DeepSeek API.

## Использование

1. Запустите `run.bat` и создайте диалог.
2. В «Управлении RAG» нажмите «Обновить документацию проекта и оба индекса».
   Кнопка копирует README.md и Markdown из docs с сохранением путей, затем
   строит fixed и structural индексы. После изменения документации повторите шаг.
3. Отправьте `/help` — локальная справка, без API и без запуска MCP.
4. Отправьте `/help Как устроен проект и где реализован RAG?`.
5. Отправьте `/help Какая сейчас Git-ветка и какие файлы есть в проекте?`.
6. Отправьте `/help Как устроены API отправки сообщения и схема диалога?`.

Для /help не нужно включать RAG в настройках обычного чата. Команда использует
structural baseline top-8: без классификатора маршрута, query rewrite и reranker.
Для вопросов со словами «схема», schema, parent_id или exchange_id добавляется
отдельный поиск top-4 по схеме данных с удалением повторных чанков.
Текущие контракты API и данных имеют приоритет над историческими отчётами дней.
Документы находятся локально; найденные фрагменты и MCP-снимок передаются DeepSeek.
В конце ответа показываются источники контекста. Это перечень переданных
источников, а не автоматическая проверка каждого утверждения или дословных цитат.

## Поток запроса и границы

`app.py: send_message` распознаёт отдельный токен /help (без учёта регистра).
Пустая команда возвращает справку. Вопрос вызывает `developer_help.project_context`:
поиск через RagIndexService и настоящие вызовы `get_git_branch` и
`list_project_files` через stdio Project MCP. Затем `Agent.reply` получает
документацию, актуальные результаты MCP и историю выбранной стратегии контекста.

Команда является read-only справкой: не выполняет файловый экспорт, произвольные
shell-команды и переходы машины задач, не запускает автоматическое извлечение
памяти. Пауза задачи и права доступа к диалогу учитываются до выполнения команды.
История и токены ответа сохраняются в обычном JSON-диалоге schema v3.

Общий и индивидуальный запреты Project MCP соблюдаются. Управление — в окне MCP рядом с настройками. При запрете или ошибке сервера модель получает
описание недоступности, а не предположение о ветке. Папка без Git и detached HEAD
имеют отдельные результаты. Перед каждым вопросом сведения Git получаются заново.
Git-ветка не индексируется в RAG: она меняется независимо от документации.

MCP показывает пути исходников из git ls-files (включая неигнорируемые новые
файлы), но исключает data, .env, модели, зависимости, рабочие результаты и
ключевые файлы. Максимум — 3000 путей с явным признаком усечения. Содержимое
исходников этим сервером не читается. Удалённые отслеживаемые файлы не выдаются.

## Источники и воспроизведение

Документация: README.md, docs/PROJECT_MAP.md, docs/API_REFERENCE.md,
docs/DATA_SCHEMAS.md и остальные Markdown-руководства docs. Архив docs/archive и исторические отчёты RESULTS, COMPARISON, SCENARIOS и CONTROL_AFTER_FIX исключены. Копии в rag_documents
игнорируются Git; канонические документы остаются в исходниках. Старый учебный
корпус и предыдущая SQLite-база удалены при переходе на день 31.

Индекс можно восстановить командой:

```powershell
.\.venv\Scripts\python.exe scripts\rebuild_rag_index.py
```

Для обновления автоматически извлечённого каталога HTTP-маршрутов:

```powershell
.\.venv\Scripts\python.exe scripts\generate_api_reference.py
```

Компактные сведения о чанках и результаты MCP сохраняются в technical ответа.
В JSON не копируются полные RAG-чанки. Текущая контрольная точка и проверки — CURRENT_STATE.md. Исторический протокол
дня 31 сохранён в archive/DAY31_RESULTS.md; он не определяет новую ревизию.
