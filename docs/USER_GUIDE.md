# Руководство пользователя

## Чат, профиль и проект

Выберите профиль в левой панели: он определяет личные предпочтения и память.
«Рабочий проект» определяет репозиторий, его документы и связанные чаты.
«＋ Диалог» создаёт независимую задачу в выбранном проекте. В узком окне
левая панель открывается кнопкой «Проекты» в заголовке чата или RAG.

«Сам ассистент» использует исходники запущенного приложения. Для другого проекта
нажмите «＋ Проект», выберите GitHub или локальную папку и укажите источник.
После подключения дождитесь индексации в «Управлении RAG». Публичный GitHub
скачивается в локальную копию; приватные URL и URL отдельных файлов не поддерживаются.
Подробные ограничения и местоположение копий — [WORKSPACES](WORKSPACES.md).

Открытие чата возвращает его проект. Переключение проекта не переносит старую
историю в новый репозиторий. Даже если имена проектов совпадают, их ID и индексы
независимы. Ранее существовавшие проекты только с памятью используют исходники
самого ассистента, пока у них нет поля workspace.

## Вопросы о проекте

- `/help` — показать локальную справку без вызова DeepSeek.
- `/help Как устроен проект?` — получить ответ по документации и свежему MCP-снимку.
- `/help Какая сейчас ветка и как связаны parent_id и exchange_id?` — совместить Git и схему.
- Обычное сообщение во внешнем workspace также получает его документацию автоматически.

Список источников в ответе показывает переданный контекст. Он сам по себе не
гарантирует проверку каждого утверждения. Проверяемый RAG — отдельный режим
обычного чата; /help использует свой упрощённый маршрут.

## Настройки и история

«Настройки запроса» задают модель и параметры следующего сообщения. Пресеты
сохраняют набор параметров. Изменение пресета не переписывает старые сообщения.
В технической информации видны фактические usage, настройки и снимки контекста.
Reasoning раскрывается отдельно, если провайдер его вернул.

Правый блок контекста содержит full/summary/sliding/facts. Ветвление сохраняет
альтернативные продолжения и работает во всех четырёх режимах. В текущий запрос
попадает только активный путь. Окна sliding/facts считаются в обменах, включая
текущее сообщение: окно 5 даёт до четырёх прежних обменов.

«Память» управляет личными и проектными записями. «Какая память использована»
у ответа показывает исторический снимок, а не сегодняшнюю отредактированную
память. Память задачи включается отдельно и сохраняет цель/решения текущего чата.
Она работает и при отключённой машине задач. См. [описание памяти](MEMORY_ARCHITECTURE.md).

## Форматирование ответов

Ответы ассистента отображаются как Markdown: двойные звёздочки или подчёркивания
дают **полужирный текст**, одинарные — *курсив*. Поддерживаются заголовки,
нумерованные/маркированные списки, цитаты, ссылки, таблицы, строчный код и
блоки кода в тройных обратных кавычках. Внутри кода звёздочки не превращаются
в выделение; длинные блоки и таблицы прокручиваются по горизонтали.

Старые сохранённые ответы также форматируются при открытии. В JSON, экспорте
и запросах к модели остаётся исходный Markdown; пользовательские сообщения
показываются буквально. Техническая информация и reasoning остаются текстом.
HTML из ответа отображается текстом, опасные URL не становятся ссылками.
Картинки показывают подпись без автоматической загрузки из сети. Подсветка
синтаксиса, математические формулы и произвольный HTML не добавлены.

## Инструменты, файлы и расписания

Кнопка «MCP» рядом с настройками открывает все три сервера. Разрешение сохраняется
для всех проектов, запуск соединения относится к показанной области. Остановка
допускает последующий автоматический запуск; запрет его блокирует.
Синяя панель в сообщении появляется только после начала вызова инструмента.

Для файлового отчёта явно попросите: «Сохрани отчёт о проекте в файл».
Filesystem разрешает модели безопасный экспорт нового Markdown в reports;
универсальное изменение исходников пока не реализовано. Артефакты машины задач
сохраняются отдельно в data/artifacts и доступны через ссылки результата.

«Расписание» открывает задания и последние запуски. Укажите самодостаточное
поручение, время либо интервал. Исполнение может расходовать DeepSeek API.
Отключение Scheduler MCP не отменяет уже созданные задания: приостановите их
в списке расписаний. См. [SCHEDULER](SCHEDULER.md).

## Ошибки и обновление знаний

После изменения README/docs нажмите обновление документации и индексов.
Если Git недоступен, ассистент должен сообщить об этом; выдуманная ветка не
считается результатом инструмента. При неготовом индексе внешнего проекта
можно начать чат, но содержимое отсутствующих документов нельзя считать известным.
Ошибочный запрос не попадает в будущую успешную историю. Проверяйте сообщение
об ошибке и request_id в журнале. Полная диагностика — [OPERATIONS](OPERATIONS.md).
