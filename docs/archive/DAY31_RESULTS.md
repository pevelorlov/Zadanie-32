# День 31: состояние и демонстрация

Старые профили, проекты, диалоги, память, пресеты, расписания и RAG удалены.
После очистки создаётся один новый основной профиль без диалогов. .env и модели
сохранены. Служебные логи, saved_runs и внешние артефакты не очищались.

RAG строится заново по README и руководствам docs, API и схемам данных.
Исторические отчёты с примерами старых диалогов исключены из индекса.
Остались Project, Filesystem и Scheduler MCP. Единственный провайдер — DeepSeek API.

Локальные тесты проверяют чат, память, RAG, /help, актуальность Git, выключатели,
файловый экспорт, планировщик и отсутствие удалённых маршрутов. Данные тестов
создаются во временных каталогах, настоящий DeepSeek не вызывается. Журнал
актуального прогона — logs/day31_cleanup_tests.log.

До очистки выполнялись живые запросы DeepSeek и настоящий stdio Project MCP.
Прямой вопрос о parent_id/exchange_id получил корректный ответ; составной вопрос
потребовал уточнения. После очистки новые платные запросы автоматически не
выполняются, чтобы оставить профиль пустым. Источники не гарантируют все утверждения.

## Сценарий видео

1. Показать чистый профиль и готовый индекс документации.
2. Создать диалог, отправить /help.
3. /help Как устроен проект и где реализован RAG?
4. /help Какая текущая Git-ветка и какие файлы есть в проекте?
5. Показать get_git_branch/list_project_files и сверить ветку в терминале.
6. /help Объясни parent_id и exchange_id в схеме диалога.

Видео записывает пользователь. Платная проверка доступна явной командой
scripts/day31_live_check.py --in-process: она создаёт демонстрационный диалог.
