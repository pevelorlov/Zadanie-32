# Архитектура приложения

## Границы системы

DeepSeek Agent — локальное Flask-приложение с браузерным интерфейсом. Генерация
ответов выполняется через DeepSeek API. Локально работают хранение, поиск,
эмбеддинги, reranker, Whisper и три MCP-сервера. Установленный пакет openai
используется как совместимый HTTP SDK к api.deepseek.com и не добавляет второго
провайдера. Названия моделей и лимиты, выставляемые приложением, см. CONFIGURATION.

Различаются корень приложения BASE_DIR и корень рабочего проекта. Приложение
может изучать собственные исходники либо подключённый репозиторий. Его серверы,
UI и код провайдера всегда запускаются из BASE_DIR; чужой репозиторий служит
источником данных. Подключение не запускает его код.

## Обычный запрос

1. UI отправляет content, settings и настройки RAG в POST messages конкретного
   диалога. Сервер проверяет формат, права профиля, состояние задачи и её паузу.
2. Рабочий проект определяется project_id **этого диалога**. Выбор другого проекта
   в интерфейсе не подменяет корень уже открытой истории.
3. Сохраняется pending-сообщение. Для контекста выбираются успешные обмены активной
   ветки, стратегия истории, профиль, проектная память, память задачи и handoff.
4. Если включён RAG, сервер выбирает маршрут и извлекает чанки. Для внешнего
   workspace включается baseline/structural/strict при наличии индекса.
5. controlled_agent_reply формирует доступный набор инструментов с учётом общего
   и индивидуальных запретов, явного экспорта и allowlist расписания. Модель
   запрашивает функции; приложение выполняет соответствующие MCP-вызовы.
6. При включённой машине задач отдельный контроллер проверяет черновик относительно
   этапа и инвариантов. Запрещённый черновик не становится успешным результатом.
   Созданные в этом проходе отчёты/расписания при блокировке откатываются.
7. Ответ, usage, источники, снимки контекста и аудит сохраняются в JSON. После
   успешного ответа могут выполняться отдельные обновления памяти задачи и
   долговременной памяти. Это дополнительные запросы DeepSeek.

При сбое пользовательское сообщение помечается failed; оно не добавляется в
будущие успешные обмены. Это не транзакция всего приложения: JSON, SQLite и
файловые результаты — разные хранилища. Параллельное развёртывание нескольких
серверных процессов с общей папкой данных не заявлено.

## Специальные маршруты

/help без вопроса возвращает локальную справку. /help с вопросом обходит
автоклассификатор RAG и машину этапов: извлекает документацию, получает свежие
ветку/список файлов и вызывает модель. Права и пауза учитываются; извлечение
памяти и файловый экспорт не выполняются. /state и /task-state показывают
локальный отчёт о состоянии.

Расписание вызывает тот же messages-маршрут внутренним Flask test_client с
профилем владельца, сохранёнными настройками и allowlist. Название test_client
здесь обозначает внутренний HTTP-клиент: реальное расписание может вызвать
платный DeepSeek API. Отдельный инструментальный MCP не является исполнителем.

## Привязка и общее состояние

Профиль и участники проекта ограничивают видимость данных внутри приложения.
Профиль выбирается в общем локальном хранилище, это не сеанс авторизации.
Глобальны пресеты, политика, выключатели MCP/машины задач и scheduler SQLite.
Отдельны для workspace документы, RAG и история сравнений; отдельно для диалога
история, ветки, task_memory, task_state и артефакты. Личная память следует за
профилем, проектная — за project_id. Подробности — MEMORY_ARCHITECTURE и WORKSPACES.


## Представление Markdown

renderMessages вызывает ChatMarkdown.renderInto только для role=assistant.
Используется локальная браузерная сборка markdown-it 15.0.3 (MIT), закреплённая
в npm lockfile. html=false запрещает HTML-разметку из ответа; разрешены обычные
относительные ссылки, HTTP/HTTPS и mailto. Ссылки получают noopener/noreferrer.
Картинки заменяются безопасным текстом подписи, не инициируя сетевые запросы.
Таблицы оборачиваются в прокручиваемый контейнер. Пользовательский текст,
reasoning и technical не передаются в HTML-парсер. Форматирование меняет только
представление; сообщения/usage/контекст и схема хранения остаются прежними.
