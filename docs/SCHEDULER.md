# Расписания и отложенные задачи

## Состав

SchedulerRepository хранит задачи и запуски в data/scheduler.sqlite3.
SchedulerService — фоновый исполнитель в процессе Flask. Scheduler MCP —
отдельный stdio-интерфейс инструментов к этому хранилищу. Его можно остановить
или запретить независимо от исполнителя. Основной запуск main.py включает
исполнитель; create_app(scheduler_autostart=False) удобен для тестов.

Часовой пояс расписаний зафиксирован в коде: Asia/Novosibirsk, UTC+07:00.
Дата без смещения трактуется в этом поясе; ISO-дата со смещением приводится к нему.
Другие записи приложения могут использовать системное время либо UTC, поэтому
сопоставлять события следует с учётом смещения в ISO-строке.

## Создание и запуск

| Вид | Поля | Поведение |
| --- | --- | --- |
| once | run_at в будущем или delay_minutes > 0 | Один запуск |
| interval | interval_minutes ≥ 5, необязательный первый run_at/delay_minutes | Повтор с интервалом не меньше 300 секунд |

Название ограничено 160 символами, prompt — 50 000. Prompt должен быть
самодостаточным поручением, а не фразой «напомни об этом». UI/API создаёт
отдельный диалог автоматизации и сохраняет owner_profile_id, project_id,
source_conversation_id и настройки модели. По умолчанию берётся выбранный проект.
Будущие исполнения используют этот связанный диалог; это не новый чат при каждом тике.

Исполнитель атомарно помечает due-задачу running и создаёт запись запуска.
Через внутренний messages-запрос передаёт prompt, сохранённые settings,
профиль владельца и allowlist инструментов. Действуют обычные ограничения
контекста, пауза и политики приложения. Само расписание не обходит запреты MCP.

Текущий KNOWN_MCP_TOOLS пуст после удаления старых внешних серверов: API
не принимает произвольные зависимости/allowlist. Обычные задания выполняются
без таких внешних инструментов; /help сохраняет собственный маршрут Project MCP
с проверкой разрешений. Создание новых расписаний из отложенного запроса
ограничено оркестрацией.

## Состояния и результаты

Задание: enabled, paused, completed, missed; running хранится отдельно.
Запуск: running, completed, failed. В запуске сохраняются scheduled_for,
started_at, completed_at, result_text, error, conversation_message_id,
duration_ms и unread. UI показывает последние результаты и уведомления;
прочтение уведомления не удаляет запуск.

После разового выполнения задание становится completed, даже если конкретный
запуск завершился failed. Ошибку проверяйте по записи запуска. Периодическое
задание после выполнения получает следующее время и возвращается в enabled.
Просроченные интервалы не догоняются серией вызовов.

При старте сервиса пропущенные разовые задачи помечаются missed, периодические
переносятся на ближайшее будущее время. Это локальный планировщик без гарантий
доставки при выключенном компьютере и без внешней очереди. Завершение процесса
может прервать активный вызов.

## Управление

В «Расписании» доступны создание, редактирование, пауза/возобновление, удаление,
списки запусков и чтение уведомлений. Сервер проверяет принадлежность задания
профилю; проект также должен быть доступен. Удаление задания каскадно удаляет
записи запусков SQLite, но не является удалением связанных чатов.

В окне MCP отдельно показано, запущен ли исполнитель. «Отключить все MCP»
останавливает инструментальные соединения, но не SchedulerService. Для запрета
конкретной платной автоматизации приостановите её в расписании. Создание/проверка
расписаний не требует генерации; их фактическое выполнение может обращаться
к DeepSeek и расходовать средства.

Реализация: scheduler.py, mcp_servers/scheduler/server.py и run_scheduled_automation
в app.py. Полный перечень HTTP-маршрутов — API_REFERENCE.md.
